# Rate limits & limits

{% hint style="info" %}
**Default limit**

Every account starts with 10 requests and 1,000,000 tokens per minute on each model (counted separately per model); all API keys of the account share the counter. See [Rate limits](../portal/rate-limits.md) for the defaults and how to request more.
{% endhint %}

## Rate limit headers

Each limit that applies to a request is reported with three headers named `x-ratelimit-{limit|remaining|reset}-{scope}-{dimension}-{window}`:

{% code title="response headers" %}
```
x-ratelimit-limit-model-rpm-minute: 10
x-ratelimit-remaining-model-rpm-minute: 7
x-ratelimit-reset-model-rpm-minute: 41
```
{% endcode %}

| Part | Values | Meaning |
| --- | --- | --- |
| `scope` | `model` · `tenant` · `key` · `key_model` · `group` · `group_model` | What the limit is counted on: `model` is your account on this model, `tenant` your whole account, `key` one API key. |
| `dimension` | `rpm` · `tpm` | `rpm` counts requests, `tpm` counts tokens — in whatever window follows. A daily request cap is `rpm-day`. |
| `window` | `second` · `minute` · `hour` · `day` · `month` | Length of the window. Day and month windows reset at 00:00 (UTC+7). |
| `reset` | seconds | Seconds until the window resets. |

## When a limit is exceeded

{% code title="429 · x-ai-error-code: request_denied" %}
```json
{"error": {"message": "model rpm limit exceeded (10/10), resets in 41s", "type": "request_denied", "code": "request_denied"}}
```
{% endcode %}

* The message names the scope and dimension that was exceeded and the seconds until it resets.
* `Retry-After` is sent when a window is exhausted. If it is absent, wait for the smallest `x-ratelimit-reset-*` value.
* A 429 with code `rate_limited` comes from the model provider, not from your limit. Retry with backoff.

## Request limits

| Limit | Value | When exceeded |
| --- | --- | --- |
| Request body size | 50 MB | `400 invalid_request`, `413` or `502` depending on the endpoint |
| Input + output tokens | `context_length` of the model | `400 invalid_request` |
| Output tokens | `max_completion_tokens` of the model | `400 invalid_request` |
| Request duration on `/v1/…` | 10 minutes without data from the model | `504` without a code |

For long generations use [streaming](streaming.md): the time limit applies to the wait between chunks, not to the whole response.

## Response headers

| Header | Description |
| --- | --- |
| `x-kong-request-id` | Unique ID of the request, on every response. Log it and quote it to support. |
| `x-ai-error-code` | Error code, on errors produced by the gateway. See [Errors](errors.md). |
| `Retry-After` | Seconds to wait before retrying; sent on some 429 and 503 responses. |
| `x-ratelimit-*` | Limits applied to the request (above). |
| `x-kong-upstream-latency` | Milliseconds spent waiting for the model. On responses that reached a model. |
| `x-kong-proxy-latency` | Milliseconds spent in the gateway. On responses that reached a model. |
| `x-kong-response-latency` | Milliseconds to produce a response generated by the gateway itself (for example a 401). |
